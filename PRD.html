1 개요

엑셀로 관리하는 방문지 주소 목록을 업로드하면 자동으로 좌표를 계산해 지도 위에 표시하고, 실제 현장을 방문했을 때 사진과 메모를 남겨 어디까지 다녀왔는지 한눈에 확인할 수 있는 도구다. 별도 서버나 로그인 없이 브라우저만으로 동작하며, PC에서 만든 결과를 그대로 모바일에서도 이어서 쓸 수 있다.

2 배경 및 문제

국내 주소 수십 건을 엑셀로 관리하고 있었지만, 위치를 한눈에 파악하거나 현장 방문 여부·메모를 기록할 방법이 없었다. 이 정도 규모에 상용 CRM이나 지도 서비스를 도입하는 것은 과도하다고 판단해, 필요한 기능만 담은 가벼운 개인용 도구를 직접 만들기로 했다.

3 대상 사용자 및 사용 환경

  • 단일 사용자를 위한 개인 프로젝트 (계정/권한 개념 없음)
  • 다루는 주소는 전량 국내 주소, 한 문서당 수십 건 규모
  • 주 사용 환경은 현장에서의 안드로이드 Chrome (5G), 보조로 PC 브라우저에서 문서 준비·확인
  • 지도·지오코딩 API 및 GitHub Pages 접속을 위해 인터넷 연결이 항상 필요 (오프라인 미지원)

4 핵심 기능

4.1 엑셀 업로드 및 파싱

  • .xlsx / .xls / .csv 업로드, 첫 번째 시트를 사용
  • 헤더가 1행이 아닌 파일(빈 행, 제목 행이 앞서 있는 경우)에 대응하기 위해 헤더 행 번호를 사용자가 직접 지정할 수 있으며, 업로드 시 "주소"가 처음 등장하는 행을 자동으로 추정해 기본값으로 채움
  • 선택한 행의 실제 내용을 미리보기로 표시해 헤더 행이 맞는지 바로 확인 가능
  • 주소 컬럼 / 표시 이름 컬럼을 드롭다운으로 선택하고, 각 컬럼의 첫 3개 값을 미리보기로 제공

4.2 주소 → 좌표 변환 (지오코딩)

  • 네이버 지도 Geocoding 서비스 사용. Client ID는 사용자가 직접 입력해 localStorage에만 저장하며 서버로 전송하지 않음
  • 요청 1건당 8초 타임아웃, 응답 없음·네트워크 오류 시 최대 3회까지 자동 재시도
  • 정상 응답이지만 주소를 찾지 못한 경우("결과없음")는 재시도 없이 즉시 실패 처리 — 재시도해도 결과가 같기 때문
  • 실패한 주소는 별도 목록으로 표시해 어떤 항목이 왜 빠졌는지 확인 가능

4.3 지도 표시

  • 변환에 성공한 주소는 마커로 표시하고, 전체 마커가 화면에 들어오도록 자동으로 중심·줌 조정
  • 메모나 사진이 하나라도 기록된 장소는 마커를 녹색 체크 아이콘으로 구분 표시해 방문 여부를 한눈에 파악

4.4 저장된 문서(데이터셋) 관리

  • 변환이 끝나면 사용자가 지정한 이름으로 좌표까지 포함해 자동 저장 (이름 미입력 시 파일명 또는 타임스탬프로 대체)
  • 동일한 이름으로 다시 저장하면 기존 문서를 덮어씀 — 이름이 곧 고유 키
  • 저장 목록에서 문서별로 불러오기(API 재호출 없이 캐시된 좌표로 즉시 표시), 재변환(주소를 다시 조회해 좌표 갱신), 삭제 가능

4.5 현장 메모 및 사진

  • 마커 클릭 시 열리는 상세 패널에서 메모 작성(입력 후 자동 저장) 및 사진 첨부(다중 선택, 모바일 카메라 촬영·갤러리 선택 모두 지원)
  • 첨부 사진은 썸네일 그리드로 표시, 클릭하면 확대(라이트박스), 개별 삭제 가능
  • 메모·사진은 주소를 키로 저장되므로 문서를 재변환하거나 같은 파일을 다시 업로드해도 그대로 유지됨

4.6 진단 및 디버그

  • 화면 하단에 디버그 로그 패널을 두어 SDK 로드, 지오코딩 성공·실패·타임아웃·재시도 내역을 실시간으로 표시
  • USB 디버깅 연결 없이도 모바일 화면만으로 현장에서 바로 원인을 확인할 수 있도록 함

4.7 전기차 충전소 인근 확인

  • 공공데이터포털에서 내려받은 전기차 충전소 CSV 파일을 업로드해 현장 근처에 충전소가 있는지 표시 (API 키·서버 호출 없이 파일만으로 동작)
  • 주소 컬럼을 지정하면 자동으로 저장되고, 이후에는 다시 업로드하지 않아도 재사용됨
  • 좌표 거리 대신 주소 텍스트 매칭으로 판정: 지오코딩 결과에서 이미 얻은 시/군/구·동·도로명이 충전소 주소에 포함되는지 확인하고, 도로명 뒤 건물번호를 추출할 수 있으면 ±30 범위로 한 번 더 좁힘
  • 인근 충전소가 있는 현장은 마커에 파란 번개 배지를 추가로 표시 — 기존 방문 표시(녹색 체크)와 동시에 표시 가능

5 비기능 요구사항

  • 빌드 도구·백엔드 없이 단일 HTML 파일로 동작
  • 무료 정적 호스팅(GitHub Pages)으로 배포, HTTPS 기본 적용
  • 데이터는 기기(브라우저)별 로컬 저장 — 기기 간 동기화는 지원하지 않음
  • 지도·지오코딩 API 키는 사용자가 매번 직접 입력하며 코드에 하드코딩하지 않음

8 배포 현황

  • 저장소 github.com/hongkyuwan/map-location (public), GitHub Pages로 main 브랜치 루트 배포
  • 서비스 주소 hongkyuwan.github.io/map-location/
  • 네이버 클라우드 콘솔의 "Web 서비스 URL"에 로컬 개발 주소와 배포 도메인을 모두 등록 완료

9 제약사항 및 트레이드오프

  • 기기 간 데이터 미동기화 — IndexedDB는 브라우저·기기 전용 저장소라 폰에서 남긴 메모/사진이 PC에 나타나지 않음. 해결하려면 별도 백엔드가 필요해 현재 범위 밖으로 둠
  • 파일시스템 직접 접근 불가 — Android Chrome이 File System Access API를 지원하지 않아, 방문지별로 실제 폴더·파일을 만드는 방식은 불가능. IndexedDB 저장 방식을 그대로 채택
  • 완전한 오프라인 미지원 — 지도 스크립트와 지오코딩 API 호출에 인터넷 연결이 필요
  • 충전소 인근 판정은 근사치 — 실제 좌표 거리가 아니라 동·도로명·건물번호 텍스트 매칭이라, 아주 긴 도로에서는 실제로 멀리 떨어져 있어도 "인근"으로 판정될 수 있음

10 해결된 이슈

개발 중 실제로 겪고 해결한 문제들의 기록.

이슈원인조치
네이버 지도 인증 실패 API 파라미터 명칭 변경 ncpClientId → ncpKeyId 해결
Web 서비스 URL 미인식 등록 주소에 포트 번호 포함 포트 제외, 호스트만 등록하도록 안내 수정 해결
엑셀 주소 컬럼 오인식 헤더에 "주소"가 없으면 자동 인식 실패 컬럼 미리보기 UI 추가 해결
변환 중 무한 정지 지오코딩 응답을 무한정 대기 8초 타임아웃 + 최대 3회 자동 재시도 해결
특정 파일에서 변환 자체가 실패 1행이 비어있고 실제 헤더는 2~3행에 위치 헤더 행 번호 지정 UI 추가 해결
"현장명+전기차 충전" 검색 결과로 판정 불가 네이버 지역검색 API는 CORS 차단 + Client Secret 노출 문제로 브라우저에서 직접 호출 불가 공공데이터(충전소 위치 데이터) 기반 근접 판정으로 방향 전환 해결
충전소 데이터가 한 사업자분만 포함 처음 선택한 한국전력공사 API는 자사 운영 충전기만 제공 전국 통합 데이터인 한국환경공단 API로 전환 시도 해결
환경공단 API 개인 활용신청 불가 공공데이터포털 활용신청이 개인 계정에는 열려있지 않음 API 호출 대신 사용자가 직접 내려받은 CSV 업로드 방식으로 전환 해결
CSV 20만 행 전체 지오코딩은 과도 CSV에 좌표가 없고 주소만 있어, 전량 지오코딩 시 API 호출량이 과도함 좌표 대신 시/군/구·동·도로명·건물번호 텍스트 매칭으로 전환 (지오코딩 불필요) 해결

11 향후 고려사항

논의는 됐으나 현재 범위에서 제외했거나 보류한 항목.

  • 보류  새로운 구현 방식으로 재시작 — 단일 HTML 파일·서버 없음 구조(v1)는 여기서 마무리하고, 이후 작업은 새 접근 방식으로 다시 진행 예정. v1 코드는 v1-single-file-final 태그로 보존
  • 보류  ZIP 내보내기 — 문서별 사진·메모를 압축 파일로 다운로드해 파일 관리자에서 열람·백업할 수 있게 하는 방안. 파일시스템 직접 접근이 안 되는 상황의 현실적 대안으로 논의했으나 아직 구현 전
  • 범위 제외  클라우드 동기화 — 여러 기기에서 동일 데이터를 공유하려면 별도 백엔드가 필요. 현재는 "한 기기에서 계속 쓰는" 시나리오로 범위를 한정
  • 보류  PWA/오프라인 고도화 — 홈 화면 추가 이상의 오프라인 지원은 아직 다루지 않음
